# LearnPulse implementation outcomes

- [x] **Faculty sections and course data** — Faculty can choose or create a section; edit and save its section code/name, course, term, faculty name/email, room, and schedule; and see those details update for the selected section. Each section keeps its own roster, subject list, marks, and course materials. Changes remain available after a browser refresh on the same device.
- [x] **Marks intake and faculty monitoring** — Faculty can upload a section's CSV/XLSX marks list; imports identify student name/roll number, numeric subject columns, and optional attendance; only the selected section's roster/marks are replaced; and the dashboard recalculates section and subject averages, best/lowest performance, improvement groups, searchable name/roll results, and attendance alerts below 75% when attendance exists.
- [x] **Individual faculty review and exports** — Faculty can open an individual student review with that section's course/faculty identity, marks, attendance, section/subject comparisons, strengths, weaknesses, recommended actions, and relevant course resources; request a detailed Groq review grounded in the uploaded marks and retrieved section data; download an individual marks CSV and a detailed report; and download section CSV/XLSX.
- [x] **Student section experience and recommendations** — A student can choose a section and then choose a student only from that section's roster; changing sections changes the roster, marks, course details, faculty name, comparisons, and materials together. The student's view includes marks, attendance, strengths, weak subjects, specific suggestions to improve, and section resources matched to their need, with optional Groq-generated advice grounded in those marks and resources.
- [x] **Course-resource retrieval (RAG)** — Faculty can add course materials to the active section with subject/topic metadata; material metadata and readable text snippets, course/faculty/section details, subject averages, and selected learner marks are included in the retrieval context; suggestions state why a resource matches; and AI output cannot claim a resource not present in the section library.
- [x] **Secure Groq service configuration** — Groq calls go through a same-origin server endpoint; the key is read only from server-side `GROQ_API_KEY`, is never exposed through a Vite client variable or localStorage, and is documented with `.env.example`; missing-key/provider errors are shown clearly; and deterministic marks/analytics remain visible independently of Groq availability.
- [x] **Responsive and runnable delivery** — The app retains the existing charcoal/orange identity, responsive layout, keyboard-usable controls, and route manifest; README documents local install, server startup, environment setup, and production build/start commands.
